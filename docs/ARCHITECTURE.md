# QuoteView 实现说明（开发向）

产品介绍见 [README](../README.md)。这里是实现细节、设计取舍、踩过的坑——给改代码的人看的。
数据源接口字段枚举另见 [data-source-fields.md](data-source-fields.md)。

## 部署工作流

源码只在开发机。编译、跑真实接口的验证都在 **corp-win**（唯一有外网的 Windows 编译机，
SSH host `corp-win`）；两台桌面（corp-win、pc-guan）只放最终 exe。

```bash
./tools/deploy.sh          # 同步源码 → corp-win 编译 + Smoke → 分发到两台桌面
./tools/deploy.sh --build  # 只编译验证，不分发
```

Smoke 打真实接口，东财 kline 偶发限流会让它中断；这种时候手动 `ssh corp-win` 直接
`dotnet publish` 跳过 Smoke 即可（App 编译不依赖接口）。exe 输出名为 `QuoteView.exe`
（`AssemblyName`），项目文件夹/命名空间仍是 `StockClient`。

## 数据保留铁律（2026-09-01）

**服务端的数据永远保留；客户端可以不保留；用户要数据时必须能从服务端取回。**

- 服务端工作集列表可截断保速度，但截掉的条目必须先写入只追加归档
  `data/archive/<kind>.jsonl`（`archive_overflow` / `cap_log`）——账户登录/配置/密码/
  异常日志、资讯出池条目均已接入；分时归档 `QV_RETAIN_DAYS=0` 永不清理；韩股档案无上限。
- 豁免：纯缓存（可从公网源随时重取的数据，如 /kline 5 分钟缓存、客户端本地各缓存）。
- 新增服务端数据种类时，默认永久保留，删除性逻辑必须先归档。

## 合约查询：排序与全量列表的两个实现约束

**结果集整体替换，不做增量 Add。** 浏览全部市场是 28,638 条，逐条塞进 `ObservableCollection`
会触发同样多次 `CollectionChanged`。`Results` 是 `IReadOnlyList<Contract>`，一次性替换 + 一次
`PropertyChanged`；`DataGrid` 开了行虚拟化。

**排序方向的状态在 ViewModel，不在 `DataGridColumn.SortDirection`。** 因为每次排序都会替换
`ItemsSource`，而 `DataGrid` 在 `ItemsSource` 变化时会把列的 `SortDirection` 清成 null——
拿它当 toggle 依据的话，第二次点击永远读到 null、永远算升序，方向死活反不过来。
`MainWindow.ResultGrid_Sorting` 接管 `Sorting` 事件（`e.Handled = true`），方向由
`MainViewModel.SortField` / `SortAscending` 决定。

## K 线图 / 分时图

- **数据源**：K 线用东财 `push2his` kline（六市场全历史，一次请求返回上市至今，不分页）；
  分时用东财 `trends2`。东财 kline 被限流时**自动切腾讯 `fqkline` 兜底**（A股/港股有历史，
  BJ/US/KR 只当天），状态栏标明来源。
- **按交易日缓存**：`KlineRepository` 缓存优先 → 东财 → 腾讯，键为 `合约/周期_复权/交易日`，
  全量历史每交易日**只拉一次**，其余读盘。这也让前复权在除权日自动正确（每交易日重拉）。
- **盘中不画当天那根**：盘中拉到的最后一根是**没走完的**（收盘价=当时价，最高/最低/成交量
  都只到那一刻）。光按交易日缓存会把这半截数据钉住一整天，收盘后再开图看到的还是它
  （v1.0.14 的 bug）。现在的规则是 **盘中直接砍掉当日那根、图止于上一交易日；收盘后读一次
  当日定稿值并缓存**。判定靠两样东西：`KlineSeries.FetchedAt` 记抓取时刻，
  `IMarketClock.IsAfterClose` 按**交易所本地时钟**判断是否已过收盘（+20 分钟缓冲，
  等收盘竞价和上游落库；港股按 16:10 收市竞价算）。缓存里只有定稿的 K 线，所以当天一直有效，
  唯一要刷新的情况是**盘中抓的、收盘后读**。一个合约每天最多两次全量拉取。
  - 砍的是「末根日期 == 当前交易日」而不是无脑砍最后一根：周末/假日的末根是上一场的、已定稿，
    不能砍。周/月线的进行中桶用**该周期内最新交易日**当标签（本周二拉是 `07-28`，周三变 `07-29`），
    同一个判断也就顺带覆盖了。
- **窗口内 30 秒静默刷新**：K 线不会跳动（进行中的那根根本没画），这个定时器只为一件事——
  窗口开着跨过收盘时自动把当日那根接上。走同一条缓存路径（收盘前每次都命中缓存、不发请求），
  `KlineChart.UpdateSeries` 只换数据、**保留缩放平移**（`SetSeries` 才重置视口），拖动中跳过。
- **降采样（LOD）**：可见根数超过像素列数时按像素聚合成合成蜡烛，绘制量恒定 ≈ 屏幕宽度，
  缩放到全部几千根也不卡（`KlineChart`）。
- 涨跌幅相对**昨收**，不是相对开盘。

## 简洁面板

- **被占的热键用 `WH_KEYBOARD_LL` 接管**：`RegisterHotKey` 先到先得，没有抢占、也没有"临时挂起对方注册"
  的接口。所以注册失败的组合改由低级键盘钩子认领——钩子在系统派发热键**之前**看到按键，吞掉就等于压过
  原占用者；退出时卸载钩子，对方的热键立刻恢复（"启动抢占、退出归还"就是这么实现的）。
  只对真正被占的组合装钩子，全部注册成功时不装。回调只比对虚拟键码 + `GetAsyncKeyState` 查两个修饰键，
  不读取/不保存/不转发任何按键，且跑在 UI 线程有系统超时，必须保持这个量级。
- **全局快捷键**（`RegisterHotKey`，注册在主窗口，进面板只是最小化）：`Win+Alt+End` 主/面板
  互切，`Win+Alt+↑/↓` 变亮暗，`Win+Alt+←/→` 切合约，`Win+Alt+PageUp/Down` 切分组，
  `Win+Alt+Delete` **循环切换面板图表**（关闭 → 分时缩略图 → 五档盘口 → 关闭）。
- **滚轮切合约**（唯一的鼠标手势；左键归拖动、右键归菜单，都不让）。两个"不灵敏"的坑：
  快速拨动时多格会**合并成一个 `Delta`**（240/360…），只走一格就跟不上，所以按 `Delta/120` 算格数
  一次到位；面板只有 20~37px 高，光标滚动中容易滑出窗口、滚轮落到下面的窗口，所以 `Root` 的
  Padding 特意留大（背景近乎全透明，看不出来，纯粹是加大命中区）。
  这是普通路由事件、不是全局钩子，只在光标位于面板上时生效；但依赖 Windows 把滚轮发给
  **悬停窗口**而非焦点窗口（`MouseWheelRouting=2`，系统默认），因为面板从不取焦点。
- **滚轮用 `WH_MOUSE_LL` 低级钩子**，不依赖系统的滚轮路由。实测日志：正常时每格都有 `WM_MOUSEWHEEL`，
  失效时**18 秒一条都没有**——系统压根不发了。它只在鼠标**移动**时决定滚轮归哪个窗口，而面板是
  分层、置顶、从不激活的窗口，判定一旦失效，光标不动就永远刷不回来（挪一下鼠标即恢复，就是这个）。
  消息没发出来，在 WPF 层还是窗口消息层接都无解。钩子里只做一件事：光标在面板 `GetWindowRect` 内
  就吞掉并投递切换，否则 `CallNextHookEx` 原样放行。**回调跑在 UI 线程且有系统超时**，所以里面
  绝不能有 IO——滚轮路径上的日志因此改成计数器，由心跳汇报。
- ~~**滚轮走 `WM_MOUSEWHEEL`，不走 WPF 路由**~~（保留为钩子装不上时的兜底）：WPF 的滚轮事件必须从 mouse-over 元素开始冒泡，而
  `Render` 每次都丢弃重建所有行、那个元素一直在消失，于是"停在原地滚几下就失灵、动一下鼠标又好"。
  窗口消息不依赖命中测试，最可靠。另外重建后仍会 `Mouse.Synchronize()`，但必须**排到布局之后**
  （`DispatcherPriority.Loaded`）——刚 `Add` 进去的行还没 measure/arrange，当场命中测试什么也找不到。
  两条路径各记一行日志，失效时能看出断在哪层。
- **滚动时不发请求、不排队重绘**：切合约会把分时的 20 秒节流清零，滚一圈就是一串请求，且每次
  `Probe.Log` 是**同步写文件**、跑在 UI 线程上——滚得越多越钝。改成切换后 400ms 静默期才抓
  （继续滚就顺延），且 `OnTick` **合并重绘**（只排一次、画最新状态，中间帧丢弃），否则每个滚轮格子
  都投一次重绘，和 1s 行情刷新一起把 Dispatcher 队列堆起来。
- **宽度只增不减**（按分组重置）：窗口 `SizeToContent`，每个合约名字长短不同，宽度实测在 141~186px 间跳。
  滚到名字短的合约时右边界回缩，**光标没动却落到了窗口外**，滚轮就归下面的窗口了——表现为"滚几下就失灵"。
- **置顶防遮挡**：`WS_EX_TOPMOST` 只保证压过非置顶窗口，任务栏也是置顶、会周期性抢到前面；
  面板 500ms 轮询检测被覆盖则重新 `NOTOPMOST→TOPMOST` 抢回（`EnsureOnTop`）。
- **面板图表**：图表块在行情行**之上**，切换时把块高差吸收进窗口 `Top`（向上生长），行情行位置不动。
  两种图共用这一块，所以一个快捷键就够（`PanelChart` 三态；旧配置的 `trend` 布尔键自动迁移，
  并继续同步写回，降级也不丢设置）。
  - **分时缩略图**：单合约、内存单日缓存、过期（>15s）重拉，线尾用 1s 现价平滑。
    **收盘后落盘**（`TrendCache`）：当天定稿后写盘、保留 7 天，之后当天再开/重启 app 零请求；
    盘中不写——序列还在长，而两个源都只能"一次返回全天"、要不到增量，半天的文件没有价值。
    所以磁盘上"存在即定稿"，读出来直接用；定稿条目在内存里也不再按 15 秒过期。线加粗并**填充到昨收基线**——
    面板不透明度可低到 20%，细线在那个透明度下看不见；横轴按整个交易日归一化（不同合约可比），早盘线本来就短。
    两源都无数据时画「分时暂无数据」，不留白（留白与"图坏了"没法区分）。
  - **五档盘口**：数据在 1 秒行情响应里就有，**零额外请求**，每 tick 直接重绘。

## 实时行情：两路轮询

主行情是**腾讯 `qt.gtimg.cn` 每 1 秒一个批量请求**（全组合约一把拉，`QuotePoller`）——价格/涨跌/量额/市值/换手/市盈市净等都在这一条里，六市场通吃。

**涨速 / 主力资金**（f22/f62/f66/f72/f78/f84/f184）腾讯没有,只东财有、且只 A 股。所以旁挂第二路
`EastMoneyExtraPoller`（东财 `ulist.np`，5 秒一个批量请求）,严格隔离:

- **按需启动**:仅当"涨速/主力净流入/…"这几列**有一列可见**时才轮询（视图监听列 Visibility → `SetFundFlowActive`）,没人看就一个请求都不发;
- 只请求活动分组里的 **A 股**,secid 用 `f13.f12` 消歧 SZ 与 BJ（两者 f13 都是 0）;
- **失败静默 + 自适应退避**（5s→翻倍到 30s,成功即恢复）,东财挂了只让这几列变旧,腾讯主链路零影响;
- 只写涨速/资金流字段,绝不碰价格,避免和 1s 价格更新互相覆盖。

## 区间涨幅：只缓存基准，涨幅本地算

昨日/3日/5日/10日/20日/60日/年初至今。要点是**区分什么才是静态的**：
"5日涨幅" = `现价 ÷ 五个交易日前的收盘 − 1`，**分子每秒都在动**——所以每天拉一次涨幅是错的
（数字会停在拉取那一刻），每天拉一次**基准价**才对。

- 东财 `ulist.np` 不给基准、只给涨幅，所以拉回来后**反推**：`基准 = 现价 ÷ (1 + 涨幅/100)`。
  涨幅两位小数 → 基准相对误差 ~1e-4，再算回涨幅落在 0.01% 内，即源数据自身精度。
  实测本地算出的值与东财同一时刻直接给的**逐项零误差**。
- **一个批量请求覆盖整组**，且**按各合约自己市场的交易日**判断是否过期——用一个全局"今天"的话，
  美股每晚跨日都会把沪深整组重拉一遍。
- 基准存单文件 `%APPDATA%\StockClient\returns\baselines.json`，每条自带交易日；
  断网/限流就继续用旧基准（只是基准旧一天），失败后 5 分钟内不重试。
- **昨日涨幅没有对应字段**（f1–f60、f100–f200 扫过都没有），用「今天的昨收 ÷ 上一条记录的昨收」推。
  所以每条会把被替换掉的那份昨收存成 `PriorClose`。两条记录相隔 **>4 个自然日**就不显示——
  没有交易日历可查，长假后宁可空一天，也不能把一周的涨幅标成"昨日"。
- **韩股拒收**：实测东财对 KR 六个周期返回同一个数，`IsUsable` 据此挡掉。

## 五档盘口

腾讯那条 1 秒批量行情的 `[9]–[28]` 就是买卖五档（价/量交替，买档从 [9]、卖档从 [19]），
原来没解析。现在解析进 `Quote.Depth`，所以盘口**不产生任何额外请求**，刷新频率天然等于实时行情。

各市场实际给到的（实测，2026-07-28）：

| 市场 | 买一/卖一价 | 挂单量 | 二~五档 |
| --- | --- | --- | --- |
| 沪A / 深A / 北交所 | 有 | 有（**手**） | 有 |
| 美股 | 有 | 有（**股**） | 无（恒 0） |
| 港股 | 有，但**就是现价回填**（买一=卖一=现价） | **恒 0** | 无 |
| 韩股 | 无（空串） | 无 | 无 |

没有价格的档位直接丢弃，所以「不提供」读出来是空列表而不是一堆 0。判"不提供"用的是
**没有任何挂单量**（`MaxVolume<=0`）而不只是空列表——港股那种一档、量 0、价格等于现价的回填，
画出来是两行一样的价格，会被读成真的买卖价差，比什么都不画更糟。这两种情况 `DepthChart`
都显示「该市场不提供盘口」。

`DepthChart` 是自绘的（每秒重绘，十几个 TextBlock 在半透明置顶窗口后面按 1Hz 重新测量正是卡顿来源），
**图表窗口（分时模式右侧）和简洁面板共用**一个控件，只差行高/字号。排版是三列：
`档位 | 价格(右对齐) | 挂单量(右对齐)`，三者**同字号同基线**——早期版本档位用 0.92× 字号、
量贴在最右边，中间空一大片，每行看着像两行。横条按**当前屏上最大挂单量**归一化、**从右侧生长**
（作为背景，不挤压数字），所以条长是"档与档之间"的相对厚度，不是绝对手数。

盘口只在**分时**模式出现：它是当日的盘口，摆在一年的日 K 旁边没有意义；切回 K 线时整列宽度收成 0。
图表窗口用**自己的**一条 1 秒行情（`TencentQuoteClient` 单合约，随分时轮询走）——因为窗口可能开在
一个不属于任何分组的合约上，没法蹭主行情那条批量请求。

## 合约备注

自由文本，**键是合约代码，不是分组**（`GroupConfig.Notes`）。备注说的是这只票本身
（"等回踩 40 加"），同一只票出现在几个分组里必须是同一条；挂在分组上的话，一票多组的瞬间就悄悄
分叉成两份。存在 `groups.json`，纯本地。

清空即删键（不存空串，免得配置攒死键）；JSON 反序列化出来的字典是大小写敏感的，而代码在别处一律
大写比较，所以 `Normalize` 里重建成 `OrdinalIgnoreCase`。

## 列设置（实时行情）

腾讯每秒行情携带的字段很多（价格/量额/市值/换手/市盈市净/振幅/均价…）+ 板块（行业/地区/概念）+ A股涨速/资金流,
默认只显示几列,其余可在**列设置窗口**（`ColumnSettingsWindow`,表头行右端齿轮按钮 / 表头右键）里配置:

- 全部列平铺成 chips,勾选显隐、**拖动排序**,带 全选/全清/默认 快捷。
- 拖拽是**鼠标捕获式**（`CaptureMouse`+`MouseMove`）,不是 OLE `DoDragDrop`——后者事件节流,浮影会卡;
  捕获式全速率跟手,浮影是拖起瞬间的**位图快照**（实时引用会因让位重建控件而变白）。
- 大数**进位显示**（`NumConverter`:3110123→311.01万,市值到亿/万亿）,悬停看真实值;下方选中行徽章保持真实值。
- 列显隐/顺序/宽度经 `QuoteColumns` 持久化（监听 Width/Visibility/DisplayIndex 三个 DP + 300ms 去抖）。

## 在线更新

启动 1.5 秒后静默首查,之后**每 30 秒**轮询;发现新版在**底部状态栏**弹提示条（更新/关闭,关闭后同版本不再自动打扰）。

- **多源顺序**:`UpdateService` 先查国内 NAS（`DomesticReleaseClient` 读 `latest.json`）,失败/超时再 GitHub
  （`GithubReleaseClient` 匿名读 `releases/latest`,**客户端不带 token**）;单源 10 秒超时,坏源快速跳过;
  GitHub 兜底自动限频 5 分钟一次,防匿名配额（60/hr）耗尽。UI 不显示来源（隐私）。
- **自更新**:下载新 exe → 把正在运行的 exe 改名 `.old` → 新 exe 就位 → 带 `--updated` 启动新进程 → 自己退出。
  单实例互斥锁对 `--updated` 会**等旧实例退出后接管**（否则新副本会把自己当重复实例退出 = "更新没重启"）。
  下次启动清扫残留 `.old`。发布见 [RELEASE.md](RELEASE.md)。

## 资讯：管道在外，客户端只读

每日简报由仓库里的 **`brief/`** 管道生成（Linux 侧，`cron` 工作日 07:30 / 15:30 两班），
客户端只负责展示。分工是刻意的：**抓取与归档在管道，判断权不在客户端**。

- **三段式**：`fetch_market.py` 抓行情 → `data/<日>/*.json`；`fetch_news.py` 抓白名单媒体原文 →
  `raw/<日>/`（含 `index.json`，每条标题带来源文件名）；`claude -p` headless 读这两个目录填模板 → `out/`。
- **两条不可妥协的约束**（写在 `brief/CLAUDE.md`）：数字只能来自 `data/`，禁止模型凭知识生成或推算；
  每条利多/利空/未证实必须标注 `raw/` 下的来源文件。抓取失败写 N/A，不允许用别的源顶替。
- **发布前有闸门**（`verify.py`）：JSON 合法性、来源文件是否真实存在、有无预测/建议类禁用词、
  指数数字是否与 `data/` 逐项一致。**不通过就不分发**。
- **分发走 HTTP**，与自更新同一条 NAS nginx 通道（`/quoteview/brief/`）：`index.json` 给日期目录，
  `brief-<日>.json` 给单日内容。客户端下载后缓存到 `%APPDATA%\StockClient\brief\`（30 天），
  先渲染缓存再拉新的，断网时看得到已读过的。
  > 早期版本是 scp 到指定几台桌面——那只覆盖管道 SSH 得到的机器，其它客户端拿不到，不是分发。
- **客户端不做任何计算**：不求和、不排序、不推导，缺值渲染成 `N/A` 而非 `0`。
  管道那头模型被禁止做算术（合计成交额、涨跌家数都由抓取层算好写死），这个保证只有在客户端
  也不偷偷补一步计算时才成立。UI 上没有预测/目标价/建议的展示位，数据结构里就没有对应字段。

## 缓存

```
%APPDATA%\StockClient\contracts\{MARKET}\{yyyy-MM-dd}\symbols.json          合约列表
%APPDATA%\StockClient\boards\{yyyy-MM-dd}\boards.json                       板块目录（行业/概念/地区）
%APPDATA%\StockClient\klines\{CODE}\{period}_{adjust}\{yyyy-MM-dd}.json     K 线
%APPDATA%\StockClient\trends\{CODE}\{yyyy-MM-dd}.json                    分时（仅收盘后定稿的）
%APPDATA%\StockClient\groups.json                                          分组 + 面板/列配置
%APPDATA%\StockClient\panel.log                                            诊断日志（默认开）
```

（`%APPDATA%` 下的目录名仍是 `StockClient`——项目/命名空间未改，只有 exe 名叫 QuoteView。）

合约列表和 K 线都按**交易日**分层，各自保留最近 **7 天**（`ContractCache` / `KlineCache`
的 `RetainDays`）。K 线的腾讯兜底数据带来源标记、不会在东财恢复后继续被当全量数据用。
K 线缓存文件还带 `FetchedAt`，用来区分「盘中抓的（缺当日那根）」和「收盘后抓的（已含定稿值）」
（见「K 线图 / 分时图」）；旧版缓存没这个字段，读出来是零值、等于「收盘前抓的」，收盘后自动重拉
一次，不需要迁移。

### 跨日：为什么用交易所本地时区，而不是客户端日期

用客户端本地日期判断"今天"，对美股是错的，而且不是"多刷一次"这种小问题：

| 北京时间 | 纽约时间 | 客户端日期规则的行为 | 后果 |
| --- | --- | --- | --- |
| 7/15 00:00 | 7/14 **12:00** 盘中 | 日期变了 → 拉取并盖戳 `07-15` | 拿到的是 **7/14** 的列表 |
| 7/15 12:00 | 7/15 **00:00** 真正跨日 | 戳 == 今天 → **不刷新** | 7/15 新股全漏 |
| 7/15 21:30–16 04:00 | 7/15 盘中 | 整场用 7/14 的列表 | **永久落后一个交易日** |

所以 `fetchedOn` 存的是**该市场本地日期**，判断也用该市场此刻的本地日期（`MarketClock`）。
夏令时交给 `TimeZoneInfo`（IANA ID 在 Windows 上经 ICU 解析），不自己算。

**为什么本地日历日 ≈ 交易日**：这六个市场的连续交易时段都不跨越各自的本地午夜
（沪深京 9:30–15:00、港 9:30–16:00、韩 9:00–15:30、美 9:30–16:00），所以本地日历日与交易日一一对应，
**不需要四国节假日表**——那种表会过期，判错就是该刷新时不刷新。

**长时间运行**：`MainViewModel` 每 15 分钟重新评估各市场（各市场跨日时刻不同，不能用一个午夜定时器）。

## 已验证的坑

**① 北交所与深A 在东财撞市场号。** 东财对北交所返回 `market 0`，与深A 完全相同，
所以**绝不能用响应里的 `f13` 反推交易所**——必须按板块 `fs` 分别拉取并由代码打标签。
后果很隐蔽：腾讯行情要 `bj920992`，写成 `sz920992` 会让该行**从响应里整行消失且不报错**。
（注：`f13` 本身仍要存下来当 K 线 secid 前缀，只是不能拿来判交易所——美股分布在 105/106/107。）

**② `pz` 被服务端硬顶在 100 条**，请求 20000 也只返回 100，必须老实分页。
但 K 线接口的 `lmt` 没有这个限制，一次返回全部历史。

**③ 北交所代码迁移**：苏轴股份东财只有新代码 `920418`，旧代码 `430418` 已不在列表
（腾讯行情仍兼容旧代码）。

**④ 东财 K 线接口会针对性限流。** 反复请求后，`push2his` 的 **kline 路径**被连接层 reset
（同 host 的 `trends2` 分时却仍通），重试无效——只能等或换源。所以 K 线做了腾讯兜底 +
按交易日缓存。

**⑤ 东财限流是按路径来的，不是按主机。** 实测同一时刻 `push2his` 的 **trends2 直接被连接层 reset**
（"基础连接已经关闭"），而同主机的 **kline 路径照常返回**。所以「东财挂了」不是全有全无——每条路径
都得自己有重试和兜底源。分时原来只有东财一个源、失败后 UI 一片空白，被报成"缩略图画不出来"
（v1.0.18 修：加腾讯 `minute/query` 兜底 + 3 次重试 + 无数据时明确写「分时暂无数据」）。

⚠️ 腾讯分时的两个语义差异：**量是当日累计值**（必须差分成每分钟量，否则量柱画成递增阶梯）；
**没有均价列**（用 累计额/累计量 反算，A股要乘 100 因为量是"手"；北交所/美股/韩股连额都没有，
均价只能是 0——消费方必须容忍，见分时图跳过均价线的处理）。

**⑥ K 线行列序是 date, open, close, high, low, …** —— close 在第三位，不是常规 OHLC。
按直觉位置读会把收盘价和最高价搞反。Smoke 有 high≥max(open,close) 的越界断言。

**⑦ 全局热键是"独占先到先得"，抢不过就得走钩子。** 同一组合只有第一个 `RegisterHotKey` 成功的进程独占，
后来者注册失败。另有键盘钩子（输入法的 Alt+Shift）会在更底层吞键，导致注册成功却永不触发。
`RegisterHotKey` 需要 GUI 线程的消息队列，所以 PowerShell 探测不了，只能在 app 里实测。

**⑧ 前复权跨除权日会整条重算。** 前复权以最新价为锚回算，每次除权，从上市到昨天的每个
前复权值都变。按交易日缓存天然规避：每交易日重拉，除权当天那次就是最新正确的。

**⑨ 东财字段号跟接口绑定，不能跨接口套用。** 例：`f127` 在 `clist` 里是市净率，在
`stock/get` 里是细分行业名。详见 [data-source-fields.md](data-source-fields.md)。

**⑩ 本机 git 传输被 DPI 封，必须走代理。** github 网页/api 直连能通，但 git 智能传输
（receive-pack/upload-pack）直连会卡死；`git config http.proxy` 指向本地代理即可。

## 已知局限

**当天新股可能当天搜不到。** 刷新点在市场本地 00:00，若东财在开盘后才把新股加进列表，
要到次日才出现。堵这个洞需要引入交易时段与节假日判断，即上面刻意避开的会过期的东西。
这种情况下直接输入完整代码仍可用。
